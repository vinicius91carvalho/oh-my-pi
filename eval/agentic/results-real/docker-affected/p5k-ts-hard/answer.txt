## What was broken

`checkPostingLive` answers `unknown` and never calls fetch when the URL cannot be parsed into a board + job id. That parse lives in `postingIdentity` (`packages/core/src/posting-identity.ts`), and its host regex only matched `boards.greenhouse.io` and `boards-api.greenhouse.io`. Greenhouse migrated postings to the **`job-boards.greenhouse.io`** domain, so every live job URL there failed to parse, the probe saw "no board, no id", and correctly refused to ask - landing on `unknown` with zero fetch calls. The adapters side already knew about `job-boards` (the convention at `board.ts:75`); the core copy of the regex had never been updated to match.

## What I changed

One line, `posting-identity.ts:89`. The host regex now reads:

```
/(^|\.)(job-)?boards(-api)?\.greenhouse\.io$/
```

that is, the exact convention the adapters already use, reused verbatim. No test was touched, no new logic.
