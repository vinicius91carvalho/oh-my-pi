One-line fix in `packages/llm/src/score-job.ts:259`: `monthlyUsdMax` computed `job.salaryMin ?? job.salaryMax` — min first — when its own docstring and the pipeline test both say the best case is `salaryMax ?? salaryMin`. **Why it was broken**
`??` returns the first non-null value, so whenever a posting listed both bounds, the function measured the floor, not the ceiling: 96k/12 = 8000 instead of 144k/12 = 12000, and BRL 8k/mo instead of 15k/mo. The bug only showed up after a rebuild because the test resolves `@fbj/llm` through `dist/`; the stale dist on disk predates the flipped line, which is why the test passed before `pnpm --filter @fbj/llm build`.

**What it means for you**
